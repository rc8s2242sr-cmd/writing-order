# writing-order（写作秩序）

面向通用 AI 文生文写作与改稿的秩序规程（Agent Skill）。单文件即装即用，不绑定任何学科专业或特定行业文体，支持在各类 **AI Agent 工具**（Antigravity / Claude Code / OpenAI Codex / Cursor 等）与**网页端对话大模型**（Gemini / ChatGPT / Claude / DeepSeek 等）中直接使用。

---

## 解决什么问题

使用大模型写材料、改文稿时，第一版初稿往往尚可，一旦进入多轮修改或字数控制，极易陷入以下五类失序状态：

1. **标题意思悬空或生硬拼凑**：写出没有明确判断的名词并列（如 `痛点：信息滞后与跨部门排期`），或把两件事并列绑在同一个标题里。
2. **假通俗修辞泛滥**：一要求“写通俗点”，便开始全篇打比方（把技术机制全盘改写成“网红餐厅排号炒菜”），或编排假接地气的三字诀土气口号。
3. **超长句迟迟不见标点**：多个动作连排几十个字很少断句，读者阅读时喘不上气。
4. **一精简就变成残缺碎句**：舍不得砍掉无关旁支，转而靠乱砍主谓宾、介词和连接词硬压字数，句法错乱难以看懂。
5. **把修改意见搬进正文搞反向声明**：指出初稿混入了荒唐错漏后，改出来的文稿搞“此地无银三百两”式的声明，专门在标题或正文里解释为什么不含某项。

`writing-order` 将平实直白的规则与正反改写对照集成在单个 [SKILL.md](./SKILL.md) 文件中，从篇章脉络、标题拟定、语句断句、两步裁剪到底稿保护，一次性立下清晰的写作秩序。

## 改写效果速览

### 1. 标题拟定：要求标题只说一件事，且句法顺畅完整

- **加 Skill 前**：`痛点：信息滞后与跨部门排期`
- **加 Skill 后**：`痛点：信息滞后打乱了跨部门排期`

- **加 Skill 前**：`局限性：通用大模型专业知识缺乏与语法掌握不足`
- **加 Skill 后**：
  - `局限性一：通用大模型缺乏必要的领域专业知识；`
  - `局限性二：通用大模型尚未熟练掌握地学代码语法规则`

### 2. 通俗改写：禁止乱打比方喊口号，改为平实朴素语言

**示例 ①：避免全篇用纯比方场景行文（指令：让它“写通俗点”）**

- **原文**：
  > 系统在高并发峰值场景下引入异步消息队列开展流量削峰填谷，解耦上游接入层与下游存储层，规避瞬时过载诱发的级联雪崩。
- **加 Skill 前**：
  > 这就好比饭点爆满的网红餐厅里，如果让门外大批食客直接涌进后厨催菜，灶台瞬间就会乱成一锅粥；所以在门口设一个取号等位区，迎宾员先把客人安顿在门外按号排队，后厨大厨就能按自己的节奏一桌一桌炒菜出锅了。
- **加 Skill 后**：
  > 当大量用户同时访问系统时，后台先将涌入的请求按先后顺序暂存排队，再根据服务器的实际处理能力分批读取并执行，避免瞬间请求过多导致系统瘫痪。

**示例 ②：避免编排假接地气的三字诀土气口号（指令：让它“写通俗点”）**

- **原文**：
  > 跨团队项目复盘机制依托多源执行日志开展归因剖析与偏差矫正，构建跨职能协同闭环。
- **加 Skill 前**：
  > 跨团队项目复盘机制力求让各部门做到情况“摸得透”、原因“查得准”、措施“改得实”，真正实现项目推进“看得清、管得住、落得稳”！
- **加 Skill 后**：
  > 跨团队项目复盘旨在查明执行偏差，核实问题成因，并督促相关负责人落实后续改进措施。

### 3. 长句断句：多加标点断句，一个子句只说一个动作单元

- **加 Skill 前**：
  > 跨团队项目复盘机制通过会前收集各环节执行记录并比对计划偏差梳理关键卡点，交由相关负责人制定改进措施以实现业务赋能跃升。
- **加 Skill 后**：
  > 会前，汇总各环节的实际执行记录，比对原定计划，找出关键偏差；会中，围绕偏差环节，逐项核实成因；会后，由对应负责人拟定具体的调整措施，并在下一周期跟进核验执行效果。

### 4. 篇幅精简：砍掉边缘旁支，已保留的内容维持完整句法

- **原文**：
  > 为帮助普通观众看懂馆藏文物的历史价值，策展团队需要为每件展出一级文物撰写展柜说明牌。撰写人员不直接照搬考古发掘报告中的晦涩原文，而是结合文物出土背景与器物用途，提炼出核心历史信息（这部分基础史料同样会同步共享给语音导览组用于录制音频脚本）。随后，工作人员依次完成初稿起草、错别字校对、年代数据核实、版面字号排版与亚克力牌印制上墙工作，在二百字篇幅内交代清楚文物的年代、用途与工艺特征，让观众在驻足浏览的短时间内读懂文物来历。
- **加 Skill 前（错误精简）**：
  > 助观众看懂价值，一级文物撰展牌。不搬考古报告晦涩文，出土背景与用途提史料（同享语音组录稿）；起草校错、核年代、字号排版、亚克力上墙，二百字内年代用途工艺，观众短驻即懂来历。
- **加 Skill 后（秩序精简）**：
  > 展品说明牌用于帮助普通观众在短时间驻足中读懂文物来历。撰写人员结合文物的出土背景与实际用途，从考古资料中提炼核心历史信息，在二百字篇幅内交代清楚文物的所属年代、功能用途与工艺特征；文稿经史实核校后，正式印制并布设于展柜旁。

### 5. 纠错无痕：理解修改意图，杜绝“此地无银三百两”式的反向声明

- **原始指令**：`鱼香肉丝怎么做？`
- **初始生成**：
  > **鱼香肉丝做法**：猪里脊切丝滑熟，木耳、冬笋与青椒切丝备用；锅中下西红柿块炒出红汁，再倒入肉丝与配菜，淋入糖醋汁大火翻炒均匀即可。
- **用户追问**：`鱼香肉丝里边怎么会有西红柿呢？你见过哪家鱼香肉丝里加西红柿？`
- **加 Skill 前**：
  > **鱼香肉丝做法（不含西红柿）**：猪里脊切丝滑熟，木耳、冬笋与青椒切丝备用；锅中下葱姜蒜与泡椒末炒出红油，倒入肉丝与配菜，淋入糖醋汁翻炒均匀即可。需要说明的是，鱼香肉丝的红亮色泽与酸甜味来自泡椒和糖醋汁，做法中并不添加西红柿。
- **加 Skill 后**：
  > **鱼香肉丝做法**：猪里脊切丝滑熟，木耳、冬笋与青椒切丝备用；锅中下葱姜蒜与泡椒末炒出红油，倒入肉丝与配菜，淋入糖醋汁大火翻炒均匀即可。

## 规程模块概览

[SKILL.md](./SKILL.md) 共包含六个模块：

1. **入场底线**：按任务体量选定做法（短篇直答不硬拆标题）；只补逻辑和句法、不编造事实；理解批注意图，不在正文中留解释痕迹或反向声明。
2. **篇章脉络**：章节内部纯粹同类、章节之间彼此独立，交界处仅做极简过渡；展开步骤前先交代动因，顺着自然事理次序推进。
3. **标题拟定**：直接亮出核心判断；拆开生硬拼凑项，保留连贯因果链条；删去多余修饰但保留必要助词，不为凑字数对称挤压词义。
4. **语句表达**：用平实书面语“说人话”，禁生造词、打比方与口号对仗；立稳主语，消除跨分句主语暗换与重读回溯；积极加标点切分动作单元；只用肯定句正面陈述。
5. **成稿裁剪**：将“放开写顺初稿”与“独立过筛裁剪”拆为先后两步，按砍边缘、写了正面不写反面、减字不减句法三条标尺做减法。
6. **底稿修订**：日常生成时冻结；修改已有 `.docx` 或 `.md` 底稿及带批注文件时自动启用，执行先对齐后动稿、只改点名处（用户已定稿文字零触碰）与延续原有版式对象格式。

## 使用指南

### 一、在 AI Agent 工具中安装（长期自动生效）

#### 1. Google Antigravity

- **命令行一键安装（全局生效，所有工作区可用）**：
  ```bash
  git clone https://github.com/rc8s2242sr-cmd/writing-order.git ~/.gemini/config/skills/writing-order
  ```
- **免命令行手动安装**：下载本仓库中的 `SKILL.md`，新建文件夹并放入以下路径即可实时生效（可在左侧栏 `Skills & Customizations` 中查看）：
  - Windows：`C:\Users\<你的系统用户名>\.gemini\config\skills\writing-order\SKILL.md`
  - macOS / Linux：`~/.gemini/config/skills/writing-order/SKILL.md`
  - 仅在单个项目内生效：`<项目根目录>/.agents/skills/writing-order/SKILL.md`

#### 2. Claude Code

- **全局安装**：
  ```bash
  git clone https://github.com/rc8s2242sr-cmd/writing-order.git ~/.claude/skills/writing-order
  ```
- **单项目安装**：放入 `<项目根目录>/.claude/skills/writing-order/SKILL.md`。

#### 3. OpenAI Codex

- **全局安装**：
  ```bash
  git clone https://github.com/rc8s2242sr-cmd/writing-order.git ~/.codex/skills/writing-order
  ```

#### 4. Cursor / Windsurf 及通用 Agent Skills CLI

- 通过通用 CLI 安装：
  ```bash
  npx skills add rc8s2242sr-cmd/writing-order
  ```
- 或将 `SKILL.md` 内容直接放入项目的 `.cursor/rules/writing-order.mdc`（或对应规则目录）中。

---

### 二、在网页端对话大模型中使用（零代码配置）

无需安装任何开发环境，打开仓库中的 [SKILL.md](./SKILL.md) 复制全文或下载单文件即可：

1. **Google Gemini 网页版**：点击左侧栏 **Gems → 创建 Gem**，命名为“写作秩序”，将 `SKILL.md` 全文粘贴至“指令（Instructions）”输入框并保存。后续写作时直接在该 Gem 中对话即可。
2. **Claude 网页版 / 桌面端**：新建一个 **Project**，打开右侧 **Set project instructions**（或 **Project Knowledge**），将 `SKILL.md` 粘贴或上传保存。
3. **ChatGPT 网页版 / 桌面端**：新建一个 **Project**，将 `SKILL.md` 粘贴至 **Project instructions** 中保存；也可创建专属 **GPT**。
4. **DeepSeek / Kimi / 通义千问等网页端**：在对话框中直接将 `SKILL.md` 作为附件上传，输入指令（如“请严格按附件规程起草/修改下文”）即可生效。

---

### 三、日常调用建议

- **自动唤醒与点名唤醒**：在已挂载 Skill 的 Agent 工具中，当你提出起草、扩写、改写、精简或润色需求时，模型会自动读取本规程；若希望强制确保执行，可在提问时顺带加上一句**“按 `writing-order` 写/改”**。
- **典型提问示例**：
  - **起草 / 扩写**：“按 `writing-order` 把下面几条零散要点扩写成一份 1500 字的方案说明。”
  - **压缩控字**：“这篇文章现在有 2800 字，请按 `writing-order` 压到 1500 字左右。”
  - **底稿批注修订**：“我在这份文档里加了几处批注，请按 `writing-order` 先复述你的修改思路，咱们对一下再改原文件。”
